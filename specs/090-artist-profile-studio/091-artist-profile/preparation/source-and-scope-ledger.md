## Every original story acceptance scenario

| Story / scenario | Expected behavior from spec (not executed) |
| --- | --- |
| User Story 1 / 1 | **Given** an existing artist with a public name, image, and biography, **When** a visitor opens the artist profile, **Then** the profile shows that name, image, and biography. |
| User Story 1 / 2 | **Given** an existing artist whose optional image or biography is missing, **When** a visitor opens the artist profile, **Then** the profile remains usable, identifies the artist by name, and presents an appropriate neutral fallback for each missing field without exposing private account data. |
| User Story 1 / 3 | **Given** an artist identifier that does not correspond to an existing artist, **When** a visitor attempts to open the profile, **Then** the visitor sees the artist-not-found outcome and no artist data. |
| User Story 1 / 4 | **Given** an artist record whose profile is not permitted to be public, **When** a visitor attempts to open the profile, **Then** the visitor sees the same artist-not-found outcome as for a nonexistent artist and sees no name, image, biography, or related content from that record. |
| User Story 2 / 1 | **Given** an artist with eligible featured songs, **When** a visitor opens the profile, **Then** the profile shows up to five songs ordered by AuraTune-recorded all-time play count descending, release date descending on equal play counts, and song ID ascending if both preceding values are equal. |
| User Story 2 / 2 | **Given** an artist with viewable albums, **When** a visitor opens the profile, **Then** the profile shows those albums and identifies each album sufficiently for selection. |
| User Story 2 / 3 | **Given** a displayed song or album, **When** the visitor selects it, **Then** AuraTune navigates to the existing destination for that content without redefining playback or album-detail behavior in this feature. |
| User Story 2 / 4 | **Given** an artist with no viewable songs or no viewable albums, **When** a visitor opens the profile, **Then** the corresponding section communicates that no content is currently available and the remaining profile stays usable. |
| User Story 3 / 1 | **Given** an artist with eligible related playlists, **When** a visitor opens the profile, **Then** the profile shows up to six public official playlists ordered by most recent update first and playlist ID ascending when update times are equal. |
| User Story 3 / 2 | **Given** a displayed related playlist, **When** the visitor selects it, **Then** AuraTune navigates to the existing playlist destination without redefining playlist-detail behavior. |
| User Story 3 / 3 | **Given** an artist with no eligible related playlists, **When** a visitor opens the profile, **Then** the profile communicates that no related playlists are currently available and the other profile sections remain usable. |
| User Story 4 / 1 | **Given** the artist identity loads but one related-content section temporarily fails, **When** the profile is presented, **Then** the loaded identity and successful sections remain available while the failed section shows a clear temporary-unavailability state. |
| User Story 4 / 2 | **Given** the artist profile data cannot be loaded at all because of a temporary failure, **When** a visitor opens the profile, **Then** the visitor sees a retryable error outcome that is distinguishable from an artist-not-found outcome. |
| User Story 4 / 3 | **Given** a failed section later becomes available, **When** the visitor retries that failed content, **Then** the section can recover without requiring navigation to a different artist profile. |

The following retains every named validation scenario and its source FR/SC links. Test implementation/execution is gated, not passed by this ledger.

| V01 — Public identity | Open `/artist/<public-id>` anonymously and as signed-in roles; public identity/sections accessible without auth hydration or refresh. | V02 — Parent privacy | Call all four artist GET paths directly for unknown/deleted/non-public/disabled IDs. Confirm same 404/code/message/data/details, no name/image/bio/content/existence/reason. Test malformed ID safely. No role bypasses public viewability. | FR-006–008, FR-018/018A; US1 |
| V03 — Featured selection | Randomize candidate order; verify eligible distinct top five using count DESC, release DESC, ID ASC, including zero. | V04 — Complete albums | Verify every eligible album, including beyond default row cap, exactly once; date DESC, title ASC, ID ASC under approved collation. Public album with no playable song follows album policy, not an invented featured-song rule. Test transport failure mid-traversal without falsely claiming completeness. | FR-007/008, FR-011/012, FR-022; US2 |
| V05 — Related playlists | Exactly official/public/qualifying playlists, ≤6; update DESC, ID ASC. Nonfeatured qualifying song counts; private/shared/nonofficial or hidden-only memberships fail. | V07 — Failure/recovery | Inject each of 7 nonempty combinations of failed/successful content sections. Identity and successful peers persist.
