## Every original story acceptance scenario

| Story / scenario | Expected behavior from spec (not executed) |
| --- | --- |
| User Story 1 / 1 | **Given** an authenticated account that does not follow a publicly accessible artist, **When** the profile's personal following state is loaded, **Then** it indicates that this account is not following the artist. |
| User Story 1 / 2 | **Given** the same account and artist, **When** the user follows the artist successfully, **Then** the account has exactly one following relationship with that artist and the profile indicates Following. |
| User Story 1 / 3 | **Given** an account already following a publicly accessible artist, **When** the user revisits the profile in a later authenticated session, **Then** the profile indicates Following for that account. |
| User Story 1 / 4 | **Given** an account already following a publicly accessible artist, **When** follow is repeated, **Then** the account remains following with exactly one relationship and the original follow time is unchanged; any duplicate outcome is reconciled without presenting a new relationship as created. |
| User Story 1 / 5 | **Given** an artist that does not exist or is no longer publicly accessible, **When** follow is attempted, **Then** no new relationship is created, the user receives the same artist-not-found outcome in both cases, without disclosure of record existence, name, image, biography, related content, visibility state, or unavailability reason. |
| User Story 2 / 1 | **Given** an account following a publicly accessible artist, **When** unfollow succeeds, **Then** the relationship is absent, the profile indicates Not following, and the artist is absent from the account's following list on its next successful load. |
| User Story 2 / 2 | **Given** an account not following an existing publicly accessible artist, **When** unfollow is repeated, **Then** the account remains not following and no other relationship changes. |
| User Story 2 / 3 | **Given** a successful unfollow, **When** the account follows that artist again successfully, **Then** exactly one new relationship exists, its follow time is the time of this new successful follow, and the personal state indicates Following. |
| User Story 2 / 4 | **Given** the authenticated account owns a relationship to an artist whose profile is hidden, **When** it sends a valid unfollow request, **Then** the relationship is removed without disclosing the artist name, image, or internal profile status; no hidden-artist interface is added. |
| User Story 2 / 5 | **Given** that hidden artist was successfully unfollowed, **When** the profile becomes public again, **Then** the artist does not reappear in the account's following list unless followed again. |
| User Story 2 / 6 | **Given** an authenticated, non-banned account sends an unfollow request using an unknown ID or the ID of a permanently deleted artist, **When** the request is evaluated, **Then** both cases return the same artist-not-found outcome without old artist information or any indication that the artist ever existed; no other relationship is changed. |
| User Story 3 / 1 | **Given** an authenticated account with followed publicly accessible artists, **When** it opens its following list successfully, **Then** each eligible followed artist appears once with a public display name and a way to open their public profile; artists followed only by another account do not appear. |
| User Story 3 / 2 | **Given** an account with no relationships, **When** its list loads successfully, **Then** it sees an explicit empty state rather than a failure or loading indicator. |
| User Story 3 / 3 | **Given** a successful follow or unfollow, **When** the personal list is next loaded successfully, **Then** membership reflects the confirmed change. |
| User Story 3 / 4 | **Given** a previously followed artist whose profile is no longer public, **When** the list is viewed or a previously known profile link is opened, **Then** restricted content is never disclosed; the artist is omitted from the list without a placeholder, the relationship and original follow time are retained, and no restricted information is displayed; opening the old link produces the same artist-not-found outcome as a nonexistent artist. |
| User Story 3 / 5 | **Given** a hidden followed artist becomes public again and the relationship still exists, **When** the list next loads successfully, **Then** the artist reappears in the position determined by its original follow time. |
| User Story 3 / 6 | **Given** followed artists with different follow times, **When** the list loads, **Then** the most recently followed artist appears first; equal times are ordered by ascending artist ID. |
| User Story 3 / 7 | **Given** the account only follows artists whose profiles are hidden, **When** the list loads successfully, **Then** the normal empty state appears without hidden-artist entries, names, images, or internal profile status. |
| User Story 3 / 8 | **Given** a mixture of public and hidden followed artists, **When** the list is shown, **Then** only public entries are represented and no count, label, placeholder, or error detail reveals hidden entries. |
| User Story 3 / 9 | **Given** an artist previously followed by the account has been permanently deleted, **When** the following list loads successfully, **Then** the artist is absent and no name, image, placeholder, count, or message reveals the deleted artist or its prior existence, regardless of how the underlying relationship is stored or cleaned up. |
| User Story 4 / 1 | **Given** no valid authenticated session, **When** follow, unfollow, or personal-list access is attempted, **Then** access requires authentication and no relationship changes or personal list is disclosed. |
| User Story 4 / 2 | **Given** authentication expires during an action, **When** authentication cannot be restored by the existing authentication flow, **Then** the user is asked to sign in again and no unconfirmed result is presented as successful. |
| User Story 4 / 3 | **Given** account A is authenticated, **When** an attempt identifies account B as the owner of a change or list, **Then** B's relationships cannot be changed or disclosed through this feature. |
| User Story 4 / 4 | **Given** a rejected change or interrupted response, **When** the result is displayed, **Then** the user receives failure or uncertainty feedback and a retry opportunity; confirmed state is preserved for a definite rejection, while an uncertain result is checked before a definitive following state is shown. |
| User Story 4 / 5 | **Given** a personal-list load fails, **When** feedback is displayed, **Then** failure is distinguishable from an empty collection and retry is available. |
| User Story 4 / 6 | **Given** account A has signed out and account B signs in, **When** personal state or a delayed result from A would be displayed, **Then** A's personal data is not shown as B's data and no pending action is reassigned to B. |
| User Story 4 / 7 | **Given** the same account sends follow and unfollow for one public artist from two devices, **When** follow is successfully processed first and unfollow is successfully processed last, **Then** the saved state is Not following and each device's next successful state or list load reflects it, regardless of click times. |
| User Story 4 / 8 | **Given** the same overlapping operations, **When** unfollow is successfully processed first and follow is successfully processed last, **Then** the saved state is Following and each device's next successful state or list load reflects it, without requiring real-time updates. |
| User Story 4 / 9 | **Given** one operation succeeds and an opposing operation fails, **When** the saved state is loaded successfully, **Then** it reflects the successful operation; the failed operation has made no change. |
| User Story 4 / 10 | **Given** an account already follows a public artist, **When** follow requests from two devices are successfully processed without an intervening successful unfollow, **Then** exactly one relationship remains and its original follow time is unchanged. |
| User Story 4 / 11 | **Given** an authenticated, non-banned account with each of the User, Artist, and Admin roles in turn, **When** it follows or unfollows a public artist and loads its own following list, **Then** the actions are allowed and only that account's relationships are returned or changed. |
| User Story 4 / 12 | **Given** each authenticated role in turn, including Admin, **When** it attempts to read another account's private following list or change that account's relationships, **Then** access is denied, no private list is disclosed, and no relationship changes. |
| User Story 4 / 13 | **Given** an unauthenticated guest or a banned account, **When** follow, unfollow, or personal-list access is requested, **Then** access is denied without changing saved relationships or disclosing the private list; public profile viewing remains governed separately by feature 091. |
