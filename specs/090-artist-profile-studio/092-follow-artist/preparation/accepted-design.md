## Concrete mapping and rollout

- Reuse 091 Artist ID/public eligibility and existing users.is_banned. No browser data import, counter, surrogate key, deletion cascade or new account-status source.
- Existing created_at is original follow time; do not rename or add followed_at. Migration `src/database/migrations/005_artist_follows.sql` captures supplied creation DDL only if absent, fails on NULL historic times without a fabricated backfill, then requires nonnull future times. Existing nonnull times remain exact. If preflight detects NULL rows, an authoritative historical source or separately approved treatment is required before live rollout.
- Auth JWT uses canonical users.user_id (current generateAccessToken); user_sessions.user_id references users.id in migration 001. Join session ownership via the actual user row, never assume the two IDs equal. Require session_id, current database account/role/ban, unrevoked/unexpired session and matching device information. No memory fallback. Existing access/refresh credentials remain unchanged.
- Backend-only service-role SQL functions execute list and desired PUT/DELETE. Lock account/session through completion; mutation locks the existing Artist row before relation checks, including an absent pair. Thus all cooperating transactions, across workers, serialize on Artist rather than an in-process mutex. Shared linked-account eligibility is rechecked with row locking and the 091 view. PostgreSQL deadlock/serialization failures roll back, never become success; client reconciles uncertain outcomes.
- Permanent deletion behavior retains supplied NO ACTION FKs; no cleanup policy is invented. Hidden owner removal is allowed, hidden without own relation and unknown/deleted return same generic 404. Duplicate PUT and public no-op DELETE return 200 without changing original time.
- SQL returns complete JSON aggregates in one snapshot, avoiding PostgREST row caps and multi-page drift. API list data is `{artists:[{id,name,imageUrl,followedAt}],complete:true}`. ID strings are cast before JSON; ordering is SQL created_at DESC, bigint artist_id ASC; wire time retains database precision.
- To prove negative state for a still-public Artist in the **same snapshot**, existing GET `/users/me/following-artists` accepts optional `artistId`. It returns the complete list only if that target is public in the list query snapshot; otherwise generic 404, with no hidden state. This is a technical recognition parameter on the existing endpoint, not a new status endpoint. Unsupported parameters/body/owner selectors are rejected. No field is added to public 091 DTOs.
- PUT/DELETE success is shared envelope with data null and generic message. List is no-store/private; safe shared 400/401/403 USER_BANNED or FORBIDDEN/404/500 errors. No new relationship/time is claimed from duplicate success. Lost responses/5xx/network failures are uncertain: read authoritative state before confirmation. No blind automatic mutation retry.
- Reuse native Node tests, existing JSX loader and PGlite from 091; concurrency across distinct PostgreSQL connections still requires a real multi-session PostgreSQL harness, not a single PGlite connection. Never claim that validation from sequential SQL tests.
- Session client captures origin generation before request/refresh/replay, aborts replay after replacement and keeps private UI volatile. Public 091 remains anonymous. Existing unrelated auth responses remain compatible; normalization is restricted to follow capabilities.
