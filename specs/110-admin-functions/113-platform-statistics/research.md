## Source conflicts requiring disposition

1. **Metric scope**: October clarification says exactly two and excludes artist/song/banned/deleted counts; November clarification and FR-002 mandate four cards and four hints. Checklist still states exactly two. Later date alone does not establish project-approved precedence. P02 needs written disposition covering every affected clause, not omission of FR-002.
2. **Play arithmetic**: FR-004 requires listening_history only, no songs.total_plays replacement/addition/synchronization. The mock adds seeded track counts and local histories. “Cumulative” and demo hint do not authorize this arithmetic. Preserve FR-004; P04/P05 must define authoritative demo attribution or leave it unresolved.
3. **System controls**: FR-021/November clarification conflict with US4, FR-008, SC-004, assumptions and checklist's read-only/no operational action scope. Separating System tab from read-only GET is a reviewable approach, not a silent source fix. P02/P11 settle whether/how it belongs to 113.
4. **No-data wording**: US2 calls for meaningful no-data states, while confirmed definitions make authoritative empty users/history equal zero. Trustworthy empty counts are zero; missing/unavailable/invalid sources are not. Exact presentation/DTO must preserve that distinction under P07.
5. **Freshness**: 113 FR-019 forbids stale values after failed refresh. Group 090 D14 permits clearly marked old Studio portions. These concern different features; do not copy the Studio fallback into 113.
6. **Historical scope**: 071 requires 365-day retention/purge and personal clear-all; 112 FR-030/093 owner D06 require preservation across content lifecycle. 113 counts retained valid history, not lifetime activity. Separate explicit retention/clear removal from later catalog/account status. P06 requires source-aligned handling, not an invented archive.
7. **Stale documentation**: 113's old absence claim for 111/112 is obsolete. 071's contract says no history endpoint exists, whereas current shared API lists POST/GET users/me/history. Use route inventory without inventing its event-ID/retry implementation. No source files changed.
